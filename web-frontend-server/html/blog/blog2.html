Nginx và cái dấu gạch chéo

27 tháng 10, 20265 phút đọc

Trang chủ của mình lên rất suôn sẻ. Vậy mà vào /blog/ thì Nginx trả về 404, dù file index.html nằm ngay đó. Mình ngồi nhìn nó gần cả buổi tối.

root và alias khác nhau thế nào?

Cả hai đều chỉ cho Nginx biết file nằm ở đâu, nhưng cách ghép đường dẫn thì khác:

  • root nối nguyên đường dẫn URL vào sau thư mục gốc. URL /blog/a.html thành {root}/blog/a.html.
  • alias thay phần khớp với location bằng đường dẫn mới. URL /blog/a.html thành {alias}a.html.

Vì alias thay thế chứ không nối thêm, nên dấu gạch chéo ở cuối mới quan trọng đến vậy.

Cái bẫy

Mình viết như sau, và nó sai:

location ^~ /blog/ {
    alias /usr/share/nginx/html/blog;   # thiếu dấu / ở cuối
}

Khi trình duyệt xin /blog/index.html, Nginx cắt /blog/ đi rồi ghép phần còn lại vào sau .../blog. Kết quả là nó đi tìm file .../blogindex.html, tất nhiên không có. Chỉ cần thêm một dấu / là chạy:

location ^~ /blog/ {
    alias /usr/share/nginx/html/blog/;
    index index.html;
}

Cách mình tìm ra lỗi

Việc hữu ích nhất mình làm là đọc log, vì Nginx ghi rõ nó đã đi tìm file ở đường dẫn nào:

docker logs web-frontend-server
docker exec web-frontend-server ls /usr/share/nginx/html/blog
curl -I http://localhost:8080/blog/

Dòng lỗi open() ... failed (2: No such file or directory) kèm đường dẫn blogindex.html chính là manh mối. Nếu mình đọc log sớm hơn thì đã tiết kiệm được mấy tiếng.

Sửa HTML xong mà trang không đổi

Website được chép vào image lúc build, nên sửa file trên máy chưa đủ. Phải build lại:

docker compose up -d --build web-frontend-server

Rồi nhấn Ctrl+F5, vì trình duyệt hay giữ bản cũ.
