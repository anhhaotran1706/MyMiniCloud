Docker là gì? Mình hiểu như sau

20 tháng 10, 20264 phút đọc

Trước môn này, câu mình nói nhiều nhất với bạn cùng nhóm là “trên máy mình chạy được mà”. Docker sinh ra để chấm dứt đúng câu đó, nên mình nghĩ nó đáng để hiểu cho đàng hoàng.

Container giống cái gì?

Cảng biển không cần biết trong thùng hàng có gì. Thùng nào cũng cùng kích cỡ, cần cẩu nào cũng nhấc được, tàu nào cũng chở được. Docker làm điều tương tự với phần mềm: nó đóng ứng dụng cùng thư viện, phiên bản và cấu hình vào một “thùng”. Máy nào có Docker thì mở thùng ra là chạy giống hệt nhau.

Image và container khác nhau chỗ nào?

Đây là chỗ mình lẫn mất một lúc. Cuối cùng mình nhớ thế này:

  • Image là bản đóng gói, chỉ để đọc, giống file cài đặt của một phần mềm.
  • Container là một lần chạy cụ thể từ image đó. Từ một image có thể chạy ra nhiều container.

Thử ngay bằng Nginx, bốn lệnh là đủ:

docker pull nginx:stable
docker run -d --name thu-nghiem -p 8080:80 nginx:stable
docker ps
docker rm -f thu-nghiem

Sau lệnh run, mở localhost:8080 là thấy trang chào của Nginx. Lệnh cuối xóa container đi, còn image vẫn nằm trong máy.

Vậy nó khác máy ảo ở đâu?

Máy ảo mang theo cả một hệ điều hành riêng, nên nặng và khởi động lâu. Container dùng chung nhân hệ điều hành của máy chủ, chỉ tách biệt phần ứng dụng, nên nhẹ hơn nhiều và bật lên trong vài giây. Đổi lại, mức cô lập của nó không chặt bằng máy ảo.

Ba lỗi mình đã gặp

  1. Gõ docker mà báo không kết nối được daemon. Lý do rất ngớ ngẩn: mình chưa mở Docker Desktop.
  2. Tạo file tên Dockerfile nhưng Windows âm thầm lưu thành Dockerfile.txt. Phải bật hiển thị đuôi file mới thấy.
  3. Cổng 8080 đang bị chương trình khác chiếm. Mình đổi thành 8088:80 là xong.

Bài sau mình kể chuyện Nginx và một ký tự làm mình mất trọn một buổi tối.
